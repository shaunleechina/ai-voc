# AI VOC 智能语义分析平台

> 基于上下文语义理解的口碑数据分析平台 —— 让每一条用户声音都被精准理解

---

## 一、项目概述

AI VOC（Voice of Customer）智能语义分析平台是一套面向汽车行业口碑数据的**语义级分析系统**。平台以"**关联上下文的语义分析**"为核心引擎，对用户评论文本进行深度理解，自动完成语义归类、情感判定与结构化标注，并输出三大代码体系（元素代码、指标代码、评价代码）的多维交叉分析视图。

与传统的"关键词匹配"方案不同，本平台基于上下文语义对文本逐句解析：同一个词在不同语境下的情感倾向会被正确区分，隐含表达（如反讽、转折、对比）也能被准确识别，标注结果具备人类分析师级别的上下文判断力。

### 核心数据规模（当前）

| 指标 | 数值 |
|------|------|
| 数据编号数 | 12 条（D2026080001 ~ D2026090012） |
| 语义标签总数 | 336 条 |
| 代码体系 | 3 套（element_code / indicator_code / evaluation_code） |
| 情感维度 | 正向褒义 / 负向贬义 / 中性 三分类 |
| 数据来源 | 抖音等短视频平台真实车主评论 |

## 二、核心功能

### 1. 标签分类分析页
按语义标签类型（match_type）聚合展示全量标注数据：
- 每个标签类型的命中数量、涉及的数据编号
- 匹配关键词（match_detail）直观呈现
- 点击钻取至逐条明细，查看原始句子与标注原因

### 2. 数据分类分析页（横向表格布局）
以"每条数据一行"的紧凑表格展示，列包含：
- **数据编号** / **数据来源** / **标签数**
- **情感分布**：彩色徽章直观显示 👍正向 / 👎负向 / ⚪中性 数量
- **匹配类型**：标签类型标签云
- **匹配关键词**：黄底高亮的关键词胶囊
- **操作**：一键打开明细弹窗

页面支持实时搜索（编号/来源/标签类型/关键词），以及两级弹窗钻取：
- **明细弹窗**：逐条展示语义标签、情感判定、标注原因、关键句子
- **原文弹窗**：展示完整原始文本（含来源、字数、时间等元信息）

### 3. 三大代码表页面
- **元素代码表（element_code）**：从车辆物理元素维度分类（外观造型、车身内装、车辆性能、驾驶感受、安全感等十大类）
- **指标代码表（indicator_code）**：从评价指标维度分类（含三级代码体系：一级分类 → 二级分类 → 三级细分指标）
- **评价代码表（evaluation_code）**：从产品/品牌/价格/服务/传播五大评价维度分类

三个页面统一采用"一级代码分组卡片"布局，每张卡片展示该分类下的情感分布统计（正向/负向/中性计数），并支持点击钻取至明细记录。一级代码的中文名称直接从各自代码表中动态读取，保证三套体系的独立性。

### 4. 情感倾向分析页
按正向/负向/中性三大情感维度聚合全量数据，展示每个情感类别的标签数量、涉及标签类型与数据编号。

```

│                    浏览器（前端）                      │
│   Jinja2 模板 + 原生 JavaScript + CSS 设计系统        │

                       │ HTTP (REST API)
┌──────────────────────▼──────────────────────────────┐
│                 Flask 应用层（app.py）                │
│   16 个路由（5 页面 + 11 数据 API）                   │

                       │ mysql-connector
┌──────────────────────▼──────────────────────────────┐
```

|------|------|

| `/api/search` | 全文搜索（标签/关键词/文本） |

## 四、数据模型

### 语义标签表（Label_data）
平台的核心产出表，每条记录代表一次"文本片段 → 代码 + 情感"的语义标注：

| 字段 | 说明 |
|------|------|
| `code_table_name` | 所属代码体系（三选一） |
| `full_code` | 命中的代码（支持三级精度，如 010201） |
| `data_code` | 数据编号（关联原始文本） |
| `match_type` | 语义匹配类型（如"语义匹配-动力响应"） |
| `match_detail` | 匹配关键词说明 |
| `sentiment` | 情感倾向（1=正向褒义 / 2=负向贬义 / 0=中性） |
| `sentiment_reason` | 情感判定理由（上下文解释） |
| `original_sentence` | 命中的原始句子（保留上下文） |

### 原始文本表（txt_data）
存放待分析的用户评论全文，含数据编号、来源渠道、文本长度等元信息。

### 三大代码表
各自独立的三级代码体系，为语义标注提供标准化的分类骨架。

## 五、技术亮点

### 1. 关联上下文的语义分析（非关键词匹配）
- 对每个句子结合**上下文语境**进行语义判断，而非机械匹配字词
- 同一词汇在不同语境下区分情感：如"动力"在"动力充沛"（正向）与"后劲偏弱"（负向）中被正确区分对待
- 隐含表达识别：转折句（"但"、"不过"后接的负面评价）、对比句式（"比…更好"）均能被精准切分

### 2. 多代码体系交叉标注
同一段文本可同时映射到三套代码体系，形成"物理元素 × 评价指标 × 用户评价维度"的三维交叉分析矩阵，为产品改进提供立体化视角。

### 3. 情感三分类 + 判定理由
每条标签不仅给出情感结论，还附带**判定理由**（sentiment_reason），保证分析结果可解释、可追溯、可审计。

### 4. 全链路可钻取
从"分类统计 → 标签明细 → 原始句子 → 完整原文"，四级钻取无缝衔接，任何统计数字都可以追溯到原始文本证据。

### 5. 统一设计系统
五个页面共享同一套 CSS 变量设计语言（色彩、圆角、阴影、动效），确保体验一致性；响应式布局适配桌面/平板/移动端。

### 6. 连接池 + 多进程部署
后端采用 MySQL 连接池复用数据库连接，Gunicorn 多 worker 并发处理请求，保证多用户同时访问时的响应速度。

## 七、应用场景

- **产品改进**：从海量用户评论中定位高频正向/负向反馈，指导产品迭代优先级
- **竞品分析**：横向对比不同车型在相同评价维度下的口碑表现
- **营销洞察**：提炼用户真实关注点与传播话题，为营销内容提供素材
- **质量预警**：负向标签集中出现的维度可快速暴露潜在质量风险
- **用户研究**：结构化的情感标注数据可直接用于用户满意度建模
